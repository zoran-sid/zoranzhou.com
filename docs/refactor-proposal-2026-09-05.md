## 1. 建议采用的方向

把主站塑造成「工程师的个人手记」：有清楚的专业背景，有值得阅读的文章，也有摄影、阅读与行走留下的个人经验。

以编辑式排版组织内容：用标题、摘要、留白、真实影像和文章选择建立气质。主站使用克制的技术视觉；Web3 Lab 延续现有独立的技术子站设计。

建议首页的阅读逻辑为：认识作者 → 阅读代表文章 → 了解当前实践 → 看见生活侧面 → 继续阅读或建立联系。

这次适合在 Astro 5、Markdown/MDX、现有内容集合与 Cloudflare Pages 上渐进改造。当前主要瓶颈在内容编排、视觉层级和可发现性，现有技术基础足以支持目标。

## 4. 首页结构

### 4.1 首屏：作者定位与探索路径图

左侧用一段准确、简洁的作者介绍建立上下文。建议文案方向：

> 在系统中求解，在世界里观察。
>
> 我是 Zoran，网络与安全工程师。这里记录我对安全系统的研究、动手构建的过程，以及阅读、摄影与行走中的见闻。

主行动为「从精选文章开始」，定位到首页精选区；次行动为「关于我」。联系入口进入关于页与页尾。WEB3 LAB 保持桌面明确入口和手机导航入口。

这是一份待实施的文案建议，不需要改变作者的真实职业经历。首屏保留姓名、专业背景与个人表达，避免用多段文字重复介绍职位。

### 4.2 雷达替代方案：探索路径图

确定采用一幅非闭环、留白充足的细线图，连接三个有具体内容支撑的方向：

- **安全研究**：AgentShield 深度分析，可点击进入文章。
- **动手构建**：现有博客搭建或 OpenWrt 实践文章，准确标注文章主题；博客搭建旧文涉及 Hugo，不把它呈现为当前 Astro 项目的实现说明。
- **行走记录**：甘孜之行、菲律宾游学或足迹中的一项，由首页编排选择。

视觉上使用一条细曲线、三个大小有区别的节点，以及简短标题和日期。每个节点使用真实链接和可读文本，完整文章标题可由正常的辅助说明提供；连接线仅作装饰，不能暗示三个主题是完成度或先后阶段。

技术实现采用 SVG 绘制装饰路径、HTML 渲染链接与文字，优先用 CSS 完成布局。首屏首次出现时可进行一次短暂描线，悬停和键盘聚焦只强调对应节点。减少动态效果时立即呈现静态完成布局。

手机端把它变为紧凑的三条内容入口，放在作者介绍之后，避免当前大雷达纵向堆叠导致首屏超过一屏。保留正常字号和足够的触摸区域。缺少同语种内容时替换为该语言的真实条目或目标栏目，不能生成不存在的译文链接。

### 4.3 精选文章：先让读者知道从哪里开始

首页首个主要内容区提供三篇精选：一篇研究分析、一篇动手实践、一篇个人经历。通过一篇较醒目的主推荐与两篇紧凑文章条目建立层级，主推荐可以随编辑意图调整。

当前可以从 AgentShield、OpenWrt 实践、2025 年末回顾中确定首轮候选。精选前检查摘要、技术内容的适用时间和文章完成度；候选不等于已经完成事实复核。

卡片包含内容类型、标题、短摘要、日期和阅读时长。选文顺序具有明确的编辑意图；现有 featured 字段可以继续使用，首页位置和跨集合选择由只保存内容引用的轻量配置控制。

探索路径图只提供短入口，精选区承担完整的阅读推荐，避免把同一篇文章的完整摘要重复排版。

### 4.4 最近更新与当前实践

精选之后使用轻量列表展示约四项最近发布/实质更新，排除已完整推荐的条目。发布日期与更新日期的含义分别标示，避免修改元数据后让旧文看起来像新文章。

当前实践放在一个紧凑区块中，每项回答：正在解决什么问题、目前进展到哪里、有什么可查看的材料。只有 in-progress 研究和 active 项目进入进行中视图；没有符合条件的内容时整块省略。

同一个项目在首页只完整介绍一次。NetGuard 需要在项目页补齐问题背景、作者贡献、演示或代码证据及局限；本轮没有核验仓库功能，不预先把描述中的全部功能视为已经验证。

### 4.5 生活片段与页尾

首页加入一张已有真实摄影作品，配合一段短文字，链接相应的游记、照片或路线。内容选取有地点、场景或个人观察，借此带出网站的生活维度。

「阅读随笔、摄影、足迹、书影音与游戏」通过生活入口连接。Media 继续以表格承载资料，不新增媒体详情页，也不恢复已移除的媒体卡片系统。

页尾用一两句话邀请继续交流，提供有效的社交链接、邮箱、RSS 与版权信息。现有 LinkedIn 为 # 占位，应补齐真实地址后展示，或先隐藏该入口。

### 4.6 首页节奏目标

| 维度       | 目标                                                                                        |
| ---------- | ------------------------------------------------------------------------------------------- |
| 首屏       | 作者定位、主行动及至少一个真实文章入口无需大幅滚动即可发现                                  |
| 桌面       | 精选文章紧接首屏，不再夹入整屏 About                                                        |
| 手机       | 在首屏或一次自然滚动内看到第一篇完整文章推荐；路径图不再形成独立的大面板                    |
| 内容密度   | 主要模块按内容决定高度，常规模块使用约 64–96px 的桌面间距、40–64px 的手机间距作为初始设计值 |
| 去重与空态 | 同一作品不重复作为完整大卡出现；无内容的首页区块不占位                                      |

## 5. 视觉系统

整体使用更安静的页面背景、大标题、精确对齐和有限的强调色，凸显文章与照片。主站保留少量线条和编号表达工程气质。

| 设计项     | 建议                                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------- |
| 浅色主题   | 暖白底色 #F7F5F0、近白内容表面、深石墨文字；蓝色作为链接及重点强调                                      |
| 深色主题   | 石墨底色约 #111318，正文更明亮；层级通过明度和细边线区分                                                |
| 强调色     | 主站以一种偏蓝的强调色为主，青色仅用于路径节点等局部；最终颜色经过可读性验证再确定                      |
| 字体       | 保留现有 Inter 与 JetBrains Mono 的本地字体基础，明确中文系统字体回退；等宽字体主要用于日期、编号和代码 |
| 中文标题   | 单独校正字距与行距，避免全站统一使用很大的负字距；长标题允许自然换行                                    |
| 内容布局   | 文章多用排版清楚的列表，精选使用少量强调区块，照片允许更大的画幅；统一基础间距与边线                    |
| 背景与阴影 | 首页局部使用浅纹理，正文区域使用稳定背景；减少多层模糊、光晕与重复描边                                  |
| 动效       | 用于导航反馈、内容展开和路径图首次呈现；滚动时无需持续追踪多层装饰                                      |

深浅主题遵循已有用户偏好。重构后的所有页面需分别验证，不能仅根据深色首页评价完成度。

## 6. 文章、实践与生活页的叙事

### 文章阅读

文章应让读者快速知道「问题是什么、适合谁、能获得什么」。长技术文章可以在开头增加简短阅读提示，复杂研究区分原始来源、自己的分析和实际验证的结论。旧教程注明适用技术和更新时间，保留历史上下文。

建议阅读顺序：类型/主题 → 标题 → 简短摘要与元信息 → 可选阅读提示 → 正文与目录 → 结论/下一步 → 相关内容。

正文宽度建议从约 42–46rem 开始调校，中文正文以 17–18px、约 1.8 行距为初始方案。手机端依据实测选择 16–17px，保证长标题和代码可读。桌面目录保持吸顶，长目录默认突出二级标题，当前章节再呈现三级标题；手机目录继续折叠展示。

技术文章可以保留适量编号与代码符号。书评与游记采用同一基础排版下的安静变体，使全局 h2 前的 // 装饰不再自动加到所有内容类型。

旧文章中的 # Section 1 等正文一级标题，需要改为有意义的章节标题并协调层级，保证文章目录可以反映内容。更改已发布标题锚点前记录旧锚点，必要时保留锚点别名，避免外部深链接失效。

相关内容的优先顺序为：作者指定的下一篇/同系列 → 同主题 → 同集合标签推荐。先复用已有相关推荐，等出现真实跨篇阅读路径时再增加关联字段。上一篇/下一篇可以保留为次级入口。

### 实践案例

项目页围绕「问题背景 → 我的职责 → 关键选择 → 实现材料 → 结果与限制 → 下一步」组织。状态、技术栈和链接是辅助信息，主要说清楚作者完成了什么。

研究页区分论文解读、设计分析和实测研究。当前短篇研究可以继续作为资料笔记完善，避免仅凭 completed 标签营造研究已经充分验证的印象。

### 生活记录

生活页先展示一个有故事的场景，再引导到不同内容载体：随笔表达思考、摄影展示观察、足迹补充路线、Media 记录看过/读过/玩过的内容。

第一版用已有正文中的链接串联游记、照片和路线。只有内容增长到手动链接难以维护时，才扩展结构化关联；不引入第二套照片或路线数据来源。

路线仍保留当前统计和地图能力，原始 GPX、稳定 routeId、分段、起终点和多语言关联按 Agent.md 的契约执行。设计调整局限在呈现层。

## 7. 代码与内容改造顺序

### 7.1 内容选择先集中

建立共享的内容查询与路径解析：公开状态、当前语言、发布日期排序、进行中状态、首页排除重复条目在同一层处理。路线继续调用现有可见性与去重函数，Lab 继续调用现有路径工具。

首页配置只保存集合与内容标识的引用、排序及必要的导读文案。文章标题、日期、描述与状态继续从原始内容读取。构建时校验引用可解析且不是草稿，避免产生另一份过时的数据。

### 7.2 样式按用途逐步拆分

从现有 global.css 中逐步提取基础 token、排版、主站外壳、首页、阅读和地图样式；基础层只保留真正全局的规则。变更一个页面类型时，同时迁出其样式并移除已替代的旧规则，避免长期叠加覆盖。

BaseLayout 专注通用文档外壳；首页的轨迹和滚动效果由首页模块负责。地图专用样式继续遵循 BaseLayout 的 mapStyles 加载契约。lab.css 保持独立命名空间。

## 9. 验证标准

- 页面与布局变更执行 npm run lint、npm run build；导航/译文改动执行 npm run test:language-routing，并覆盖真实译文与缺失译文两种情况。
- 如修改路线展示，按 Agent.md 检查桌面/手机地图、闭环起终点与深浅主题；只有变更解析、身份或统计逻辑时才扩展对应数据测试。
- 内容字段扩展时检查 schema → 旧内容 → 页面 → i18n → 搜索/RSS/sitemap → 本地编辑器字段保留；触及编辑器时执行其专用检查。
- 在 390px、768px、1280px、1440px 等宽度核对主要布局；至少覆盖中英文、深浅主题、长标题、表格、代码、空集合、手机菜单与减少动态效果。
- 文章与导航在没有动画时仍完整可用；搜索、菜单和目录可使用键盘操作；横向滚动限制在必要的代码/表格容器内。
- 比较旧版和新版的 URL 清单、canonical、hreflang、RSS 和搜索落点。普通详情不盲目替换语言前缀。
- 构建输出继续为 dist，Pages Function 仍仅服务根语言重定向；产物扫描不包含本地编辑器、文件写入 API、设置与备份。

性能以正式测量建立基线，再比较改造前后。可采用真实用户第 75 百分位 LCP ≤ 2.5 秒、INP ≤ 200 毫秒、CLS ≤ 0.1 作为目标，并区分桌面和手机数据；没有足够真实用户数据时，仅报告实验室结果，不能声称 INP 已经达标。这些阈值来自 [Web Vitals 官方说明](https://web.dev/articles/vitals)。
